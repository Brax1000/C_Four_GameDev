# C-Four: Bomb Defusal Simulator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Windows console C game where the player defuses a C4 by entering a hidden code before a live countdown ends.

**Architecture:** Five modules (`main`, `menu`, `game`, `round`, `display`), one `.c` plus `.h` each, in the repo root. `game.c` is pure logic and is the only module with automated tests; the Windows-console modules are verified by compiling and by a manual playtest. Dependencies flow one way: `main` -> `menu`, `round`; `round` -> `game`, `display`; `menu` -> `display`; `game` -> stdlib only.

**Tech Stack:** C99, MinGW gcc or Code::Blocks, `conio.h`, `windows.h`, ANSI escape codes. No external libraries.

**Spec:** `docs/superpowers/specs/2026-10-20-c-four-design.md`

**Spec amendments (flag at review):**
1. `game_remaining_ms` is added to `game.c` (spec put the timing math in `round.c`) so it can be unit-tested without Windows headers. `round.c` calls it.
2. Tests live in `tests/` so the spec's `gcc ... *.c` build in the root does not pick up a second `main`.
3. `display_flush_input` lives in `display.c` as a console helper so `menu` and `main` need no `conio.h` of their own.
4. Menu keys: `1`, `2`, `3`. Play-again keys: `Y` / `N` (either case).

## Global Constraints

- Target: Windows only (Command Prompt / PowerShell / Windows Terminal); C99; no external libraries.
- Game build: `gcc -std=c99 -Wall -Wextra *.c -o cfour.exe` (run in repo root).
- Presets: Normal 4 digits / 90 s / 5 s penalty; Intermediate 5 / 75 / 10; Hard 6 / 60 / 15.
- Code: each digit independently random 0-9 (repeats and leading zeros allowed), stored as a null-terminated char array, max 6 digits.
- Enter submits only when all N slots are filled; Backspace erases; all other keys ignored; no guess cap.
- Remaining time: `seconds*1000 - (now_ms - start_ms) - penalty_ms`, using `GetTickCount64()`; lose when `<= 0`; `Sleep(50)` per loop; timer redraws only when the displayed second changes; shown as `MM:SS`, red at 10 s or less.
- History panel shows the most recent 8 guesses. Layout about 80x25. Redraw with `ESC[H`, never a full clear per frame.
- Startup: `SetConsoleOutputCP(CP_UTF8)` and enable `ENABLE_VIRTUAL_TERMINAL_PROCESSING`; if ANSI cannot be enabled, fall back to uncolored output.
- `srand(time(NULL))` once, in `main`.

## Review Focus

1. Arrow and function keys: `_getch()` returns a prefix (`0` or `0xE0`) then a second byte; the second byte must be swallowed, never read as input. (Task 7)
2. Keys typed or held during the end screen or menu must not answer the next prompt: stale input is flushed before every prompt and at round start. (Tasks 6, 7, 8)
3. Console window smaller than 80x25: warn and wait instead of drawing wrapped garbage. (Tasks 4, 8)
4. Ctrl+C or any exit must not leave the console red, with a hidden cursor or in the wrong code page. (Task 4)
5. A penalty that lands remaining time exactly on 0 or below zero is a loss, and the timer never displays a negative value. (Tasks 3, 5)

static void test_generate_code_shape(void) {  /* srand(12345) first */
    char code[MAX_DIGITS + 1], first[MAX_DIGITS + 1]; int differs = 0;
    for (int n = 4; n <= 6; n++)

        }
    assert(differs);
}
